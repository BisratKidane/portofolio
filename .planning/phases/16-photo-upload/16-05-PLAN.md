## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Any authenticated user → any member's photo (read) | D-07's deliberately broad view boundary — no scope check by design |
| Member-user → another member's stored photo (write/delete) | Editable-scope boundary, same as upload |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-13 | Information Disclosure | Unauthenticated read of a member's photo | mitigate | `requireAuth` gates every GET request; no JWT, no photo |
| T-16-14 | Elevation of Privilege | Removing a photo for a member outside the actor's editable scope | mitigate | Identical `computeEditableScope` check reused from the upload route |
| T-16-15 | Information Disclosure (accepted, by design) | Any authenticated user can view ANY member's photo, not just their own scope | accept | D-07 is an explicit, locked product decision — this app treats all authenticated users as trusted family for viewing; writing stays scope-gated |
