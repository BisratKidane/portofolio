# Phase 16 — UI Design Contract

> Visual and interaction contract for the member profile-photo surfaces (PHOTO-01..03). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design-system note:** This app already ships a complete, centralized design system — MUI 6 + Emotion driven by a single theme (`frontend/src/theme.js`). The shadcn gate is **not applicable**: a design system *is* detected, and introducing a second one mid-milestone would break the visual consistency the theme guarantees. Every token below is **pre-populated from the existing theme, the shipped `/manage` surfaces, and the Phase 15 UI-SPEC** — nothing invented, nothing re-asked. This contract's job is to lock (a) which existing tokens the photo surfaces reuse and (b) the phase-new interaction, state, and copy surfaces the avatar-upload flow introduces.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (established MUI 6 + Emotion theme — `frontend/src/theme.js`) |
| Preset | not applicable |
| Component library | MUI 6 (`@mui/material`) on Emotion; primitives this phase: `Avatar`, `ButtonBase`, `Dialog`, `DialogTitle`, `DialogContent`, `Slider`, `Button`, `Alert`, `Skeleton`, `Stack`, `Box`, `Typography`, `Tooltip` |
| Third-party UI component | `react-easy-crop` ^6.2.2 — crop viewport only (D-02); styled via its `style`/`classes` props, **no CSS-in-JS conflict with Emotion** (verified in RESEARCH.md Standard Stack) |

**Reuse mandate:** the crop dialog mirrors `EditMemberDialog.jsx` structure exactly — `<Dialog fullWidth maxWidth="sm">` → `<DialogTitle>` → `<DialogContent>` → `<Stack spacing={2} sx={{ pt: 1 }}>` with an inline `<Alert severity="error">` at the top of the stack and a trailing `<Stack direction="row" spacing={2}>` action row (primary first, `Cancel` second). The remove-photo confirmation mirrors `ManagePage.jsx`'s "Remove member?" dialog (Cancel left, destructive confirm right-aligned). Page chrome comes free from `AppLayout`.

## Spacing Scale

MUI base spacing unit = **8px**. Scale is carried forward verbatim from the Phase 15 contract — no new tokens this phase.

| Token | Value | MUI shorthand | Usage in this phase |
|-------|-------|---------------|---------------------|
| xs | 4px | `0.5` | Gap between zoom label and slider |
| sm | 8px | `1` | Dialog content `pt: 1`; gap between avatar and its remove-photo action on `xs` |
| md | 16px | `2` | `Stack spacing={2}` in the crop dialog; action-row gaps; MemberCard row spacing (unchanged) |
| lg | 24px | `3` | Crop-viewport-to-controls separation; dialog inner padding |
| xl | 32px | `4` | Vertical break between the crop viewport block and the action row on `sm+` |

Exceptions (all concrete, all multiples of 4):

- **Avatar sizes (established, unchanged):** 42×42 in `/manage` member rows and relationship panels, 48×48 in the crop dialog's "current photo" reference if rendered. Nav avatar (38×38) is the **account** avatar and is out of scope — it keeps `getInitials`, never a member photo.
- **Touch target for the avatar trigger:** the 42×42 avatar is wrapped in a `ButtonBase` with `minWidth: 44, minHeight: 44` and `borderRadius: '50%'` — the hit area clears 44px while the avatar's rendered size stays 42px. This is the only place a non-`Button` element becomes interactive this phase.
- **Crop viewport height:** `320px` on `xs`, `360px` on `sm+` (`sx={{ height: { xs: 320, sm: 360 } }}`), full dialog width, `position: relative` (required by `react-easy-crop`).
- **Border radius:** inherited — dialog/paper **5px**, buttons/inputs **3px**. Crop shape is `round` with `aspect={1}` (avatar is always circular).
- **Camera-overlay affordance:** full-bleed circular overlay on the 42px avatar; icon rendered at **20px** (`fontSize: 20`).

## Typography

Carried forward from Phase 15 / theme. Two working UI weights: **400** (regular) and **600** (semibold); **700-Sora** is the established heading treatment, not a third UI weight.

| Role | Variant | Size | Weight | Line Height | Usage in this phase |
|------|---------|------|--------|-------------|---------------------|
| Dialog heading | `h6` (via `DialogTitle`) | 20px (1.25rem) | 700 (Sora) | 1.6 | "Crop photo", "Remove photo?" |
| Body | `body1` | 16px (1rem) | 400 | 1.5 | Confirmation body copy; member name in cards keeps `fontWeight: 600` |
| Label / meta | `body2` | 14px (0.875rem) | 400 | 1.43 | "Zoom" slider label, helper text ("JPEG, PNG or WebP · max 5 MB"), all `color="text.secondary"` |
| Button | `button` | 14px | 600 | 1.75 | "Save photo", "Cancel", "Remove photo" — `textTransform: none`, never uppercase |

No new type tokens. The placeholder avatar renders an **icon, not initials** (D-10) — `getInitials` must not be used as the member-avatar fallback anywhere on member surfaces after this phase.

## Color

60/30/10 split drawn directly from `theme.js` `colors`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f6fb` (`colors.bg`, fixed radial-gradient body wash) | Page background behind all photo surfaces |
| Secondary (30%) | `#ffffff` (`colors.paper`) with `1px solid #e6e8f0` (`colors.line`) | Member cards, dialog surface, crop-dialog chrome |
| Accent (10%) | `linear-gradient(135deg,#6366f1→#a855f7)` (`colors.gradient`); solid `#6366f1` (`colors.primary`) | See reserved list below |
| Destructive | `#ef4444` (`colors.error`) | The **Remove photo** confirm button and its dialog only |

Accent reserved for (explicit — never "all interactive elements"):

1. The crop dialog's **Save photo** contained CTA (`containedPrimary` gradient fill).
2. The **camera hover/focus overlay** on an in-scope avatar: `rgba(99,102,241,0.55)` scrim (primary at 55%) with a white `PhotoCameraRoundedIcon`.
3. The **focus-visible ring** on the avatar trigger: `outline: 2px solid #6366f1; outline-offset: 2px`.
4. The crop dialog's **Zoom `Slider`** (`color="primary"`, solid `#6366f1` — not the gradient).

Neutral (NOT accent):

- **Placeholder avatar (D-10):** `bgcolor: '#eef1f8'`, icon color `#64748b` (`colors.slate`) — identical to the existing initials-avatar treatment in `MemberCard.jsx`, so unphotographed members look exactly as they do today apart from the icon swap.
- **Crop viewport backdrop:** `#0f172a` (`colors.ink`) — a neutral dark field so the cropped region reads clearly; not a brand surface.
- **Remove photo** trigger button in the card row: `variant="text"`, default (neutral) color. Only the *confirmation* button is `color="error"`.
- Loading `Skeleton`: MUI default neutral.

Only ONE additional semantic color (destructive) is load-bearing this phase. `colors.warning` is **not** used.

## Copywriting Contract

Voice: sentence case, plain and reassuring, verb-first buttons, never uppercase — matching Phase 15.

| Element | Copy |
|---------|------|
| Primary CTA (crop dialog) | **Save photo** — in-flight label: **Uploading…** (disabled) |
| Secondary action (crop dialog) | **Cancel** (`variant="text"`; discards the selection, no request sent) |
| Avatar trigger — no photo, in scope | Tooltip + `aria-label`: **"Add a photo for {fullname}"** |
| Avatar trigger — has photo, in scope | Tooltip + `aria-label`: **"Change photo for {fullname}"** |
| Avatar — out of editable scope | Not interactive. No tooltip, no overlay, no `aria-label` beyond the `Avatar`'s `alt={fullname}` |
| Crop dialog helper text | "Drag to reposition, zoom to frame. JPEG, PNG or WebP · max 5 MB." |
| Zoom control label | **Zoom** (`body2`, `text.secondary`) |
| Remove-photo action (card row) | **Remove photo** (neutral text button; rendered only when a photo exists **and** the actor is in editable scope) |
| Empty state — member has no photo (D-10) | No text. A generic `PersonRoundedIcon` placeholder on `#eef1f8` — **never initials**, never a "no photo" caption cluttering the row |
| Error — file too large (client pre-check + server 400) | "That photo is larger than 5 MB. Zoom in to crop a smaller area, or choose a different photo." |
| Error — unsupported/unrecognized format (server magic-byte reject, D-06) | "That file isn't a JPEG, PNG or WebP image. Choose a photo in one of those formats." |
| Error — outside editable scope (403) | "You can only change photos for yourself and your close relatives." |
| Error — generic upload failure (network/500) | "Couldn't upload that photo. Check your connection and try again." |
| Error — photo fails to load in an avatar (blob fetch fails) | **No error text.** Fall back silently to the `PersonRoundedIcon` placeholder — a broken decorative image must never produce an alert |
| Destructive confirmation — Remove photo (D-11) | Title: **Remove photo?** Body: "Remove {fullname}'s photo? Their avatar goes back to the default icon. This can't be undone." Confirm: **Remove photo** (`color="error"`, in-flight label **Removing…**); Cancel is neutral and left of the confirm |

**Naming collision guard:** the existing admin **Remove** action (deletes the *member*, `color="error"`) and the new **Remove photo** action (neutral text) sit in the same card row. They must stay visually distinct — the member action keeps error color, the photo action stays neutral — and their confirmation dialogs use distinct titles ("Remove member?" vs "Remove photo?"). Do not shorten "Remove photo" to "Remove".

All error copy is rendered as `<Alert severity="error">` at the top of the crop dialog's `Stack` (per `EditMemberDialog` precedent), or — for errors raised before the dialog opens (format/size rejected at file-pick time) — in the same `Alert` with the dialog opened to the error state rather than silently swallowing the pick.

## Interaction States

Every state below must be reachable and visually distinct. This is the phase's real UI surface.

| Surface | State | Contract |
|---------|-------|----------|
| Avatar (`MemberAvatarImage`) | no photo | `PersonRoundedIcon` on `#eef1f8` / `colors.slate`, `aria-hidden` on the icon, `alt={fullname}` on the `Avatar` |
| Avatar | fetching blob (D-09) | `<Skeleton variant="circular" width={42} height={42} />` — only when `photoUrl` exists; never flash a skeleton for a member with no photo |
| Avatar | loaded | `<Avatar src={objectUrl} alt={fullname} sx={{ width: 42, height: 42 }} />`; object URL revoked on unmount / `photoUrl` change |
| Avatar | fetch failed | Silent fallback to the placeholder state |
| Avatar trigger | idle, in scope | Plain avatar — no persistent overlay (keeps the row calm) |
| Avatar trigger | hover / focus-visible, in scope | Primary scrim + white `PhotoCameraRoundedIcon` (20px); focus-visible adds the 2px primary outline ring. `cursor: pointer` |
| Avatar trigger | out of scope | Static `Avatar`, no `ButtonBase` wrapper, no `cursor: pointer`, not tabbable |
| File input | — | Visually hidden `<input type="file" accept="image/jpeg,image/png,image/webp" />`, reset (`value = ''`) after each pick so re-picking the same file re-fires `onChange` |
| Crop dialog | open | Crop viewport (`aspect={1}`, `cropShape="round"`, `showGrid={false}`) on `colors.ink`; Zoom `Slider` min `1`, max `3`, step `0.1` |
| Crop dialog | submitting | **Save photo** → **Uploading…**, both buttons disabled, dialog non-dismissible (`onClose` no-ops while in flight — matches the delete-dialog precedent) |
| Crop dialog | error | `<Alert severity="error">` at the top of the stack; buttons re-enabled so the user can retry or cancel |
| Crop output | — | Square **512×512**, `canvas.toBlob('image/jpeg', 0.9)` — a D-04-accepted format, deterministically well under the 5 MB cap |
| Remove-photo flow | confirm dialog | Non-dismissible while removing; **Remove photo** → **Removing…** |
| After success (upload or remove) | — | Dialog closes, the member's avatar updates in place (refetch, no full-page reload, no toast — matches the existing save-and-refetch pattern) |

**Accessibility contract:** the avatar trigger is a real focusable control (`ButtonBase`, keyboard-activatable via Enter/Space) with an `aria-label` that names the member; the crop viewport is decorative-but-interactive and is preceded by the helper text so screen-reader users get the constraints before the control; the `Slider` carries `aria-label="Zoom"`; the placeholder icon is `aria-hidden` with the accessible name carried by the `Avatar`'s `alt`.
