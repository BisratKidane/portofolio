<objective>
Build the pure, exhaustively-testable view-frame reducer that models descendant
navigation: which person is at the top of the current 3-generation view, whether
their children are shown, which single child (if any) is drilled into, and a
history stack that makes a grandchild-triggered forward-shift (NAV-04) exactly
invertible by collapsing (D-04).

Purpose: This reducer is the single source of truth for NAV-02/NAV-03/NAV-04's
correctness. It has zero React/DOM dependency so every invariant (one-branch-only,
exact shift/undo symmetry, structural 3-generation cap) is provable with plain
`expect(fn(input)).toEqual(output)` assertions — no component rendering needed.
Plan 27-03's `useDescendantNav` hook imports this reducer unchanged; get the
push/pop pairing right here and the "back to exactly where I was" guarantee holds
for the whole phase.

Output: `frontend/src/hooks/descendantNav.reducer.js` (+ test), the first pure
reducer module in this codebase.

<!-- Reference shape from 27-RESEARCH.md Pattern 1 / 27-PATTERNS.md — already vetted
     against CONTEXT.md D-01..D-04 and ROADMAP's NAV-01..04 success criteria. Plan
     27-03 imports this EXACT contract (function names, action-type strings, and the
     frame's field names) — do not rename or restructure. -->

State shape: { topId, topExpanded, expandedChildId, history: [] }
  - topId: id of the person currently at the top of the 3-generation view
  - topExpanded: whether topId's children (gen1) are shown
  - expandedChildId: id of the single gen1 child currently drilled into (or null) —
    a scalar, never a Set/array (Pitfall 1: keeping this a scalar is what makes
    D-01's "only one branch open" true by construction, not by extra imperative code)
  - history: array of PRIOR frame objects, pushed verbatim on each forward-shift,
    popped verbatim on the walk-back-up collapse (D-04)

Exports:
  initial(topId) -> { topId, topExpanded: false, expandedChildId: null, history: [] }
  navReducer(state, action) -> newState

Action types (plain string `type`, no external constants needed):
  - { type: 'RESET', id } -> initial(id) — used on a search-driven mainPerson change;
    the CALLER (Plan 27-03's hook) is responsible for NOT clearing its cache here —
    this reducer only resets the FRAME.
  - { type: 'EXPAND_TOP' } -> toggles topExpanded. If currently expanded AND
    history.length > 0, POP the last history entry and return it verbatim with the
    remaining history (walk-back-up, D-04). If currently expanded AND history is
    empty, ordinary collapse: topExpanded:false, expandedChildId:null (D-02). If
    currently collapsed, topExpanded:true (unchanged topId/expandedChildId/history).
  - { type: 'EXPAND_CHILD', id } -> if expandedChildId === id, collapse (set null,
    D-02). Otherwise overwrite expandedChildId with id (D-01: overwriting a single
    scalar field is what makes expanding a second sibling auto-collapse the first —
    no explicit "collapse the old one" step is needed or should be added).
  - { type: 'EXPAND_GRANDCHILD', id } -> PUSH the entire current state object onto
    history (not a reconstruction — the exact object), then return
    { topId: state.expandedChildId, topExpanded: true, expandedChildId: id,
      history: [...state.history, state] }. NAV-04: the parent (previous
      expandedChildId) becomes the new top; the grandchild (id) remains its child;
      no separate "does this grandchild have children" guard is needed here —
      PersonCard (Phase 25, unchanged) never renders an expand control for a
      childless card, so this action can only ever fire for an eligible grandchild
      (Pitfall 2 — do not add a redundant guard here).
  - default -> return state unchanged.
</interfaces>
