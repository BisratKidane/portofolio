# Phase 15 — UI Design Contract

> Visual and interaction contract for the `/manage` self-service page (MNG-01..04) and the REL-06 dedup error surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Design-system note:** This app already ships a complete, centralized design system — MUI 6 + Emotion driven by a single theme (`frontend/src/theme.js`). The shadcn gate is **not applicable**: introducing a second design system mid-milestone would break the visual consistency the theme guarantees, and 15-CONTEXT.md (Claude's Discretion) explicitly directs "follow existing `AdminLinkMembers.jsx` conventions." Every token below is **pre-populated from the existing theme and shipped pages** — nothing invented, nothing re-asked. The contract's job here is to lock which existing tokens `/manage` must reuse and to specify the phase-new interaction/copy surfaces.

## Spacing Scale

MUI base spacing unit = **8px**; all shipped pages use multiples of it via `Stack spacing` and `sx` shorthand. 8-point scale confirmed.

| Token | Value | MUI shorthand | Usage (as shipped) |
|-------|-------|---------------|--------------------|
| xs | 4px | `0.5` | Chip inner padding, icon gaps |
| sm | 8px | `1` | Compact inline spacing (nav button gaps) |
| md | 16px | `2` | Default element spacing (`Stack spacing={2}`, row gaps) |
| lg | 24px | `3` | Card padding (`p:3`), section spacing, grid gaps |
| xl | 32px | `4` | Section breaks (`Stack spacing={4}`), row `px` at `md` |
| 2xl | 40px | `5` | Hero/panel padding at `md` (`p:{xs:3, md:5}`) |
| 3xl | 56px | `7` | Page top/bottom padding (`Container py:{xs:4, md:7}`) |

Exceptions:
- Border-radius tokens (px, from theme overrides): inputs/buttons **3px**, cards/paper/panels **5px** (`borderRadius:5`), stat tiles **4** (`borderRadius:4`), chips **2px**. `/manage` panels use the 5px card radius; the add-dialog inner form fields use the 3px input radius.
- Avatar sizes (established): **42×42** in list rows (reuse for member cards), **38×38** nav, **48×48** stat-tile icon frame. Row Avatar 42px is the `/manage` member-card standard.
- Touch targets: MUI `Button` default `paddingBlock:9 / paddingInline:20` and 40px+ input height already clear the 44px-comfortable bar; no per-phase override.

## Typography

Pulled from theme + shipped usage. Sans (Inter) carries body/UI at weights **400** and **600**; the display font (Sora) carries headings at **700**. Treat 400 (regular) and 600 (semibold) as the two working UI weights; 700-Sora is the established heading treatment, not a third UI weight.

| Role | Variant | Size | Weight | Line Height | Usage on `/manage` |
|------|---------|------|--------|-------------|--------------------|
| Page heading | `h5` | 24px (1.5rem) | 700 (Sora) | 1.334 | "Manage family" page title; panel titles ("System users" pattern) |
| Section heading | `h6` / `subtitle1` | 20px (1.25rem) / 16px | 700 (Sora) / 600 | 1.6 / 1.5 | Relationship group labels — **You / Parents / Spouse / Children / Siblings** |
| Body | `body1` | 16px (1rem) | 400 | 1.5 | Member name in cards (`fontWeight:600` emphasis), dialog field values |
| Label / meta | `body2` | 14px (0.875rem) | 400 | 1.43 | Sub-labels, emails, muted meta (`color="text.secondary"`) |
| Eyebrow | `overline` | 12px | 700 (uppercase, `letterSpacing:0.12em`) | 1.4 | Small section eyebrows / stat labels (optional, matches Dashboard) |

Buttons: `textTransform:none`, weight 600 (theme default) — never uppercase button labels.

## Color

60/30/10 split drawn directly from `theme.js` `colors`. The page background + card surfaces dominate; the indigo→violet gradient is the reserved accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f6fb` (`colors.bg`, with the fixed radial-gradient body wash) | Page background behind all `/manage` content |
| Secondary (30%) | `#ffffff` (`colors.paper`) with `1px solid #e6e8f0` (`colors.line`) borders | Relationship-group panels, member cards, admin table surface, dialog surface |
| Accent (10%) | `linear-gradient(135deg,#6366f1→#a855f7)` (`colors.gradient`); solid `#6366f1` (`colors.primary`) | See reserved list below |
| Destructive | `#ef4444` (`colors.error`) | Admin **Remove member** action + its confirm dialog only |

Accent reserved for (explicit — never "all interactive elements"):
- The **primary contained CTA** in each context: `+ Add {relationship}` section buttons, and the dialog's **Add member / Create & link** submit (gradient fill, `containedPrimary`).
- The **actor's own ("You") card** highlight and the linked-account Avatar (gradient fill, matching Dashboard's ADMIN avatar treatment).
- Small informational **Chips** (e.g. member count, role) using `colors.gradientSoft` bg + `colors.primaryDark` text (Dashboard pattern).

Secondary/neutral (NOT accent): `#a855f7` violet only inside the gradient; `#64748b` (`colors.slate`) for muted text/secondary avatars (`#eef1f8` bg); `#e6e8f0` for dividers/borders. Picker/edit/back actions use `variant="text"` or `variant="outlined"` (neutral), never the accent gradient.

Semantic secondary: `#f59e0b` (`colors.warning`) is available for the **"add a parent first" inline notice** and the **"manages their own profile" locked-relative hint** if a tinted affordance is wanted; otherwise render those as neutral `text.secondary` captions. Only ONE additional semantic color (destructive) is load-bearing this phase.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Page heading | **Manage family** — subtitle: "Add and edit the relatives you're connected to." (admin subtitle: "Search the whole tree and manage any member.") |
| Primary CTA (member view) | Per section: **Add parent** · **Add spouse** · **Add child** · **Add sibling** (verb + relationship) |
| Primary CTA (add dialog) | **Add member** (create-new path); reuse **Create & link** wording only on the admin account-link path (matches `AdminLinkMembers.jsx`) |
| Secondary action (dialog) | "or pick someone already in your family" (in-scope picker toggle); **Back** / **Cancel** to dismiss |
| Empty state — no relatives (member) | Heading: **Just you so far.** Body: "Add your parents, spouse, or children to start building your branch of the family." |
| Empty state — siblings (derived) | "No siblings yet — they appear automatically once you and another child share a parent." |
| Empty state — admin search no match | "No members match your search." |
| Empty state — admin no unlinked accounts | "No accounts are waiting to be linked." (carried verbatim from `AdminLinkMembers.jsx`) |
| Error — REL-06 dedup (the phase's signature error) | "A child named '{firstname}' already exists under {sharedParentFullname}. Pick a different name, or edit the existing member." (names conflicting member + shared parent, per D-08/specifics) |
| Error — add-sibling with no parent (Phase 14 D-04) | Inline: "Add a parent first — siblings are derived from a shared parent." (rendered before/inside the sibling dialog, not a dead-end submit) |
| Error — generic load/mutation failure | `<Alert severity="error">{err.message}</Alert>` — surface the server message via `graphqlRequest` (established pattern) |
| Locked-relative hint (D-06) | Card shows no edit button + small caption: "Manages their own profile." |
| Derived-sibling affordance (D-02) | Small `Chip` / caption on sibling cards: "Derived" (tooltip/hint: "from a shared parent") — never an editable edge |
| Destructive confirmation — Remove member (admin only, D-07) | Dialog title: **Remove member?** Body: "Remove {fullname} from the family tree? Blood relatives are preserved. This can't be undone." Confirm button: **Remove** (destructive/error color); Cancel is neutral. |

Voice: sentence case, plain and reassuring; buttons are verb-first and never uppercase. No em-dash-heavy or jargon copy. Match the calm, first-person "your family" framing from CONTEXT.md specifics.
