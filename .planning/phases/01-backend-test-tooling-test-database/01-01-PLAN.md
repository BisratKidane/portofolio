Key fact: `dotenv.config({ path: process.env.ENV_FILE || defaultEnvPath })` runs as a **top-level side effect at module import time**. Whoever imports `env.js` (directly or transitively) first — with whatever `process.env.ENV_FILE` is set to at that moment — determines which env file wins for the entire process (ESM module caching). `backend/vitest.config.js` must set `process.env.ENV_FILE` and `process.env.NODE_ENV` as the literal first statements, importing nothing but `defineConfig` from `vitest/config` (which does not transitively import `env.js`).
