<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| test process → MySQL server | `globalSetup` opens a real DB connection and issues destructive DDL (`sync({force:true})`, `drop()`) |
| MySQL container init → app DB user grants | The init script grants database-level privileges to the existing app user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-1-01 | Tampering | `backend/test/globalSetup.js` + `backend/test/guard.js` (`sync({force:true})` / `drop()`) | mitigate | D-05 two-signal guard (`NODE_ENV==='test'` AND `DB_NAME` ends `_test`) runs synchronously in `globalSetup`, before any DB module is even imported — a failing guard means no connection is ever opened. Independently, `sequelize.sync({ force: true, match: /_test$/ })` adds Sequelize's own built-in regex safety net as defense-in-depth. Both must agree before any destructive call executes. Automated positive/negative-path coverage via `backend/test/guard.test.js` (Task 1). |
| T-1-02 | Elevation of Privilege | `backend/test/init/01-create-test-db.sh` `GRANT` statement | mitigate | `GRANT` is scoped explicitly to `portofolio_test.*` only — no `*.*`, no `CREATE DATABASE`/`DROP DATABASE`, no superuser grant — matching D-01's least-privilege stance for the harness. The app DB user's existing dev-DB privileges are unchanged. |

No high-severity unmitigated threats remain for this plan.
</threat_model>
