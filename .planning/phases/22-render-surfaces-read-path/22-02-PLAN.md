export function getGeezDisplay(member) {
  const text = member?.geezFullname?.trim();

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Server-fetched member data → React render | All three components render `member.geezFullname`, a string that ultimately originates from another family member's own profile data (entered via Manage in a future phase, but already persisted and already fetched by an authorized GraphQL query today). No new network call, no new user-input path, no new persistence — this is a pure render-path retrofit of already-fetched props. |
| Admin search box → client-side filter | `AdminMemberTable`'s search term is client-side-only, filtering an already-fetched, already-authorized in-memory array via plain string `.includes()` — no server round-trip, no query construction from user input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-02 | Tampering / Information Disclosure (stored-XSS-via-rendered-name) | `MemberNode.jsx`, `AdminMemberTable.jsx`, `MemberCard.jsx` — all render `geez.text` (derived from `member.geezFullname`, ultimately user-entered) as React `Typography` children | accept | React auto-escapes all text-node content by default; none of these three edits introduces `dangerouslySetInnerHTML` or any raw-HTML rendering path — `geez.text` is rendered exactly like the pre-existing `member.fullname` (already rendered as plain text everywhere in this app). The `lang` attribute value (`geez.lang`) is not raw user input — it is a hardcoded constant (`GEEZ_LANG = 'ti'`) sourced from the locked Phase 21 helper, never derived from member-supplied text. No new sanitization is required beyond React's existing default. |
| T-22-03 | Denial of Service (ReDoS via search input) | `AdminMemberTable.jsx` search filter | accept | The filter uses plain `String.prototype.includes()`, not a user-constructed `RegExp` — there is no regex-compilation step and therefore no ReDoS surface, regardless of how long or adversarial the typed search string is. |

No other STRIDE categories apply: this plan adds zero new endpoints, zero new mutations, zero new auth/session logic, and zero new external dependency.
</threat_model>
