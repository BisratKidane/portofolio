<objective>
Close the sole remaining Phase 11 gap (VERIFY-04): the shipped `verifyEmail` ADMIN promotion is two separate, non-transactional autocommit statements that verification independently reproduced as non-atomic under real MySQL 8.4 concurrency (28/30 trials raised an unhandled `ER_LOCK_DEADLOCK`, burning the losing racer's single-use token with no recovery path). Per the user's locked decision (CR-01 Option B), make token-consumption + admin-count check + promotion one atomic Sequelize transaction using a locking `SELECT ... FOR UPDATE` read, add retry-once-on-deadlock error handling so a losing racer still gets a valid session, replace the misleading in-code atomicity comment, and replace the inadequate `Promise.all` race test with a deterministic, controlled-delay two-connection harness that would actually fail if the guarantee regressed.

Purpose: Achieve the phase's headline deliverable — "closing the first-user-becomes-ADMIN land-grab race" — with a real, DB-enforced atomicity guarantee instead of an unverified, timing-dependent one, so VERIFY-04 can be re-verified and Phase 11 can close.
Output: A race-safe `verifyEmail` resolver (one transaction, locking read, deadlock retry, accurate comment) and a `verifyEmail.test.js` concurrency test that deterministically proves the guarantee and would catch a regression.
</objective>

| Concurrent HTTP clients -> `verifyEmail` mutation | Untrusted request *timing* (not just payload) crosses into a DB-consistency-critical section — two legitimate, honestly-timed requests racing each other is itself the threat surface, not malicious input. |
| `verifyEmail` resolver -> MySQL | The admin-count read/promotion depends on lock semantics being correctly requested (`FOR UPDATE`) and correctly scoped (one transaction) — a regression here silently reopens the race even though every unit test that only exercises the happy path would still pass. |
