## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `sequelize.sync()` (ORM-managed schema) vs. a real, already-provisioned dev/prod database | `sync()` never alters an existing table's columns — covered by the migration plan (11-03), not this one |
| `getUserFromRequest` central gate vs. per-resolver checks | The gate is the single choke point every protected resolver relies on transitively via `requireAuth`; a bypass here is a bypass everywhere |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01a | Elevation of Privilege | `getUserFromRequest` central gate | mitigate | `if (!user.emailVerified) return null;` inserted directly in the shared auth-resolution path (not duplicated per-resolver), proven by a dedicated positive/negative test pair (Task 2, Test 5/6) — closes the "hidden in UI only" failure mode explicitly called out by ROADMAP SC-3. |
| T-11-01b | Tampering (token) | `createVerificationToken`/`hashVerificationToken` | mitigate | Token is `crypto.randomBytes(32)` (256 bits of entropy, unguessable) and only its sha256 hash is ever intended to be persisted (enforced by the resolvers built in Plan 11-04/11-05); this plan proves the helper functions themselves are correct in isolation. |
| T-11-01c | Denial of Service (test-suite regression) | `backend/test/helpers.js` `createTestUser()` | mitigate | Default flipped to `emailVerified: true` so the new column's restrictive default doesn't silently fail dozens of unrelated pre-existing tests; explicit override path preserved for tests that need an unverified fixture. |
