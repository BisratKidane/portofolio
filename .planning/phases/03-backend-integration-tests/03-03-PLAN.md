```javascript
requestPasswordReset: async (_parent, { email }, { models }) => {
  const user = await models.User.findOne({ where: { email: email.toLowerCase().trim() } });
  const message = 'If the account exists, a password reset token has been generated.';
  if (!user) return { message, resetToken: null };

  const resetToken = createResetToken();
  user.resetPasswordToken = resetToken;
  user.resetPasswordExpiresAt = resetTokenExpiry();
  await user.save();

  return { message, resetToken };
}
```

<!-- .planning/codebase/CONCERNS.md — source content for the KNOWN-ISSUES.md entry (Security Considerations section). -->
```markdown
**Password reset token exposed to anyone who requests it (account takeover):**
- Risk: `requestPasswordReset` returns the freshly generated `resetToken` in the mutation response to whichever caller invoked it — not only to the account owner via email.
- Files: `backend/src/resolvers/user.resolver.js:48-61,63-74`, `frontend/src/pages/ForgotPassword.jsx:7-11`
- Current mitigation: None at the API layer.
- Recommendations: Never return `resetToken` over the API/network. Deliver it exclusively via a verified email channel.
```
