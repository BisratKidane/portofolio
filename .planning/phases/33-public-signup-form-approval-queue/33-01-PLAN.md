<objective>
Build the phase's single highest-value artifact — the D-04 client/server validation-agreement contract — and widen `AuthContext.jsx`'s `register()` to a named-object parameter that both the invited and the (upcoming) public signup path can call.

Purpose: this is Wave 0 per `33-VALIDATION.md`. Phase 32's CR-01 shipped a client-side guard more permissive than the server's, and it survived TDD + mutation testing because every test checked the guard against itself. This plan makes that class of bug structurally impossible for the new public form: the agreement test imports the *real* backend policy modules and asserts client-accepts ⇒ server-accepts. It also removes the positional-argument footgun in `register()` before a second call site (the public form, Plan 33-04) is added.
Output: `Register.validation.js` + its agreement test (consumed by Plan 33-04), and a widened `AuthContext.jsx` `register()` (consumed by Plan 33-04's rewritten `Register.jsx`; the invited path in `Register.jsx` keeps working unchanged against the new signature).
</objective>
