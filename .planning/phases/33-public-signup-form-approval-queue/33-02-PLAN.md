<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| anonymous public internet ↔ `users.name` / `users.relationshipNote` columns | Both fields originate from an unauthenticated `register` call (Phase 32) and are rendered verbatim to an authenticated ADMIN on this queue — the admin queue is the first surface in the app that displays attacker-controlled free text to a privileged user |
| admin browser ↔ `approveUser`/`rejectUser` mutations | Card actions must address the exact account the admin is looking at, with no stale/orphaned indirection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-02 | Tampering / Information Disclosure | ApprovalsPage.jsx note & name rendering | mitigate | Render `relationshipNote` and `name` as plain React string children only (`Typography` `body1`/`h6`) — never `dangerouslySetInnerHTML`, never a markdown renderer; Task 2's new test asserts an HTML-bearing note renders as literal text, not as a DOM element (SEC-03 UI half) |
| T-33-01 | Elevation of Privilege | ApprovalsPage.jsx approve/reject wiring | mitigate | `pendingApprovals` returns flat `User` rows; APPROVE/REJECT now address `row.id` directly (no `row.registeredUser` indirection, no `orphaned`/`blocked` dead branch) — a stale or null account reference can no longer be silently mis-approved or leave a row permanently un-actionable |
| T-33-02-05 | Spoofing | Whole approval queue (confused-deputy input) | accept | CR-02 (account pre-hijacking via a forged relationship note/name pair the admin has no way to verify) is a locked, accepted risk per CONTEXT.md D-01 / `.planning/todos/pending/20260903-cr02-account-pre-hijacking.md` — not re-mitigated in this phase |
| T-33-02-06 | Denial of Service (partial, UX-level) | ApprovalsPage.jsx load() state machine | mitigate | `error` and `rows === null` are checked as mutually exclusive branches, `error` first, so a failed fetch can never render an infinite spinner stacked under an error banner (SC-5) |
</threat_model>
