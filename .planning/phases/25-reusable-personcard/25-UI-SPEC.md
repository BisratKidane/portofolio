# Phase 25 — UI Design Contract

> Visual and interaction contract for the reusable `PersonCard` component. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase ships the `PersonCard` **component only** (plus its spouse-rendering). The `/detail` page, its states, the search bar, the responsive generation grid, the expand/collapse + forward-shift mechanics, and the wiring of the admin add/edit dialogs belong to Phases 26–28. `PersonCard` exposes props/callbacks (`role`, `spouse`, `expanded`, `onExpand`, `onEdit`) that those phases drive.
>
> **Source of truth:** All tokens below are drawn from the existing MUI theme (`frontend/src/theme.js`, the app-wide `colors` object) and the locked decisions in `25-CONTEXT.md` (D-01…D-14). This is not a greenfield design — `PersonCard` reuses the app's established gender/spouse/Ge'ez conventions in a roomier vertical geometry.

## Spacing Scale

The project uses MUI's 8px spacing unit. Declared 4-based scale for the card:

| Token | Value | MUI | Usage on PersonCard |
|-------|-------|-----|---------------------|
| xs | 4px | 0.5 | Icon-to-label gaps (role/status rows), ge'ez-to-latin name gap |
| sm | 8px | 1 | Compact stacking between name block and meta rows |
| md | 16px | 2 | Card inner padding, avatar-to-text-block gap |
| lg | 24px | 3 | Vertical rhythm between avatar zone and footer control zone |
| xl | 32px | 4 | Gap between a person card and its lateral spouse card (dashed-connector span) |
| 2xl | 48px | 6 | Reserved for grid gutter (Phase 27 grid; card must not assume it) |
| 3xl | 64px | 8 | Not used at card scale |

**Exceptions:**
- **44px minimum touch target** for both interactive controls — the top-right edit `IconButton` (D-08) and the bottom-edge expand control (D-07) — matching the existing `MEMBER` badge/avatar pattern (`minWidth: 44, minHeight: 44` in `MemberNode.jsx` and `MemberCard.jsx`). This satisfies the A11Y-01 hit-target requirement carried into Phase 29.
- **Avatar ring thickness** (gender cue, D-09) is a `border`/`box-shadow` width of **2–3px**, not a spacing token.

## Typography

Four roles on the card. Weights constrained to **two** used values: **500 (medium)** for secondary/meta text and **700 (bold)** for names and the emphasized name line — consistent with the existing family cards (`MemberNode.jsx` uses 700 for names, 500–600 for meta).

| Role | Size | Weight | Line Height | Font | Notes |
|------|------|--------|-------------|------|-------|
| Name — Latin (`fullname`) | 16px | 700 | 1.25 | Inter | Primary identity line; `noWrap` with ellipsis (D-04) |
| Name — Ge'ez (`getGeezDisplay`) | 18px | 700 | 1.30 | Abyssinica SIL | Rendered `lang="ti"`, only when present (D-04); tinted with the gender color per the `/family` convention |
| Role / status label | 12px | 700 | 1.40 | Inter | Uppercase-ish role chip (`Head`/`Child`/`Grandchild`, D-05) and the `Living`/`Deceased` status chip (D-04); letter-spacing 0.04em |
| Meta / control label | 14px | 500 | 1.50 | Inter | Child-count copy (`1 child` / `N children`, D-07) and any secondary line |

Body line-height 1.5, heading (name) line-height 1.2–1.3 per house convention.

## Color

The app is a light theme (`colors.bg` page, `colors.paper` cards). The 60/30/10 split for the `/detail` surface hosting this card:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f6fb` (`colors.bg`) | Page background behind the cards (owned by the /detail page, Phase 26) |
| Secondary (30%) | `#ffffff` (`colors.paper`) | The card surface itself, overlaid with a soft gender tint (`{genderTint}14` ≈ 8% alpha, per `MemberNode.jsx`) and a 2px gender-colored border |
| Accent (10%) | `#6366f1` (`colors.primary`, indigo) | Interactive affordances only: the expand chevron control, the edit `IconButton`, and the `:focus-visible` ring |
| Destructive | `#ef4444` (`colors.error`) | **Not used this phase** — no destructive action on the card |

**Accent reserved for:** the expand/collapse control, the admin edit icon button, and focus-visible outlines. Never applied to plain text, borders of non-interactive elements, or the whole card.

**Gender is a separate semantic channel (not the 10% accent).** Per D-02, gender is encoded on the card via border + soft background tint using the app's established mapping (do not invent new values):

| Gender | Tint (`genderTint`) | Source |
|--------|--------------------|--------|
| Male | `#3b82f6` | `MALE_TINT`, `MemberNode.jsx` |
| Female | `#ec4899` | `FEMALE_TINT`, `MemberNode.jsx` |
| Other / unknown / undefined | `#64748b` (`colors.slate`) | `genderMeta` fallback — never breaks layout (CARD-03/D-02) |

**Contrast:** The Ge'ez name line is tinted with `genderTint`; the male `#3b82f6` and slate `#64748b` clear WCAG AA on white, but `#ec4899` (female) on white at 18px/700 is borderline — Phase 29 (A11Y-01) must verify AA; if it fails, darken the tint for the text line only (keep the lighter tint for the border/fill) rather than changing the border color. Flag for the checker.

## Component Anatomy & Interaction Contract

`PersonCard` is a **props-only, page-agnostic** component (mirrors `MemberNode`'s `data`-bag pattern). It owns no data-fetching, routing, or navigation state.

**Props (contract for Phases 26–28):**

| Prop | Type | Drives |
|------|------|--------|
| `member` | `FamilyMember` (Phase 24 shape: `fullname`, `geezFullname`, `gender`, `isAlive`, `photoUrl`, `children[]`, `spouses[]`, `canEdit`) | All rendered fields |
| `role` | `'Head' \| 'Child' \| 'Grandchild' \| undefined` | Role label (D-05); rendered only when provided |
| `spouse` | `FamilyMember \| undefined` | The single lateral spouse card (D-12/D-14); when present, renders a second `PersonCard` with `isSpouse` beside this one, joined by the dashed connector |
| `isSpouse` | `boolean` (default `false`) | When `true`: no child-count/expand control (D-13), no lateral spouse of its own |
| `expanded` | `boolean` | Chevron direction state; behavior is Phase 27 |
| `onExpand` | `(member) => void` | Fired by the expand control; no-op wiring this phase |
| `onEdit` | `(member) => void` | Fired by the edit button; wired to `EditMemberDialog` in Phase 28 |

**Layout zones (vertical card, D-01/D-03 — fluid width, height-to-content):**
1. **Top-right:** admin edit `IconButton`, rendered only when `member.canEdit === true` (D-08).
2. **Avatar zone:** prominent `MemberAvatarImage` (reuse; supports `variant`/`fill`) wrapped in the **gender ring** — border-style encodes gender as the always-on non-color cue (D-09): e.g. **solid = Male, dashed = Female, dotted = Other**. Works over a real photo or the gendered `MemberFallbackAvatar` (D-10, `aria-hidden`).
3. **Identity block:** Latin `fullname` (16/700), then Ge'ez name (18/700, `lang="ti"`, only when present), then role label + `Living`/`Deceased` status chip.
4. **Footer control zone (blood-line cards only):** child-count + expand affordance along the bottom edge, shown only when `member.children.length >= 1` (D-07/CARD-04). Count from `children` array length (no `childCount` field — Phase 24 D-05).

**States:**

| State | Rendering |
|-------|-----------|
| Field absent (any of Ge'ez name, role, etc.) | Omit the element entirely — no empty label, no "N/A", no reserved gap (CARD-01/D-04) |
| `children.length === 0` | No expand control, no `0 children` text (CARD-04) — never a disabled/empty control |
| `expanded === true` | Chevron points up / rotated; accessible name flips to "Hide children of {name}" |
| `expanded === false` | Chevron points down; accessible name "Show children of {name}" |
| Gender unknown/undefined | Slate ring (dotted) + slate tint; layout unchanged (CARD-03/D-02) |
| Spouse present | Second card (`isSpouse`) rendered laterally + dashed connector; spouse carries no expand control (D-13) and does not count toward the generation cap (SPOUSE-01/D-12) |
| Avatar photo loading/broken | Handled inside `MemberAvatarImage` (skeleton → silent fallback); card shows no error |

**Accessibility (CARD-03 + A11Y-01 forward-looking):**
- Card `aria-label` includes gender: `` `${fullname}, ${genderLabel}` `` and a `data-gender` attribute for tests (mirrors `MemberNode.jsx`, D-11) — gender never conveyed by color alone for AT.
- Gender ring shape (D-09) is the always-on **visible** non-color cue (color-alone was rejected).
- Both controls are real buttons (`IconButton`), keyboard-focusable, with `:focus-visible` outline `2px solid #6366f1` offset 2px (existing house pattern).

## Copywriting Contract

`PersonCard` has no traditional page-level CTA; its interactive copy is the expand affordance and the accessible labels. The `/detail` page owns page-level empty/error/loading copy (Phase 26) — this card only omits absent fields.

| Element | Copy |
|---------|------|
| Primary control label (expand) | `1 child` (singular) / `{N} children` (plural) — count from `children.length` (D-07/CARD-04) |
| Expand control accessible name | Collapsed: `Show children of {fullname}` · Expanded: `Hide children of {fullname}` |
| Edit control accessible name | `Edit {fullname}` (icon-only button; visible on `canEdit === true`, D-08) |
| Role label | `Head` / `Child` / `Grandchild` (supplied via `role` prop, D-05) |
| Status chip | `Living` (isAlive !== false) / `Deceased` (isAlive === false) — mirrors `MemberDetailPanel.jsx` (D-04) |
| Gender label (aria/data only) | `Male` / `Female` / `Other` (D-11) |
| Empty / absent field | No copy — element omitted entirely (CARD-01); never `N/A`, never an empty label |
| Empty state (no children) | No copy and no control rendered (CARD-04) — the card is complete without it |
| Error state | Not owned by this component — the /detail page renders failed-request/missing-info states via existing components (Phase 26, DETAIL-03) |
| Destructive confirmation | None — no destructive action on the card this phase (edit/add wiring is Phase 28; no delete) |
