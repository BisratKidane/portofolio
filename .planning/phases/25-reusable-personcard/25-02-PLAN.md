D-14 spouse-selection helper (documented for Phase 26/27's caller contract —
NOT implemented in `PersonCard.jsx` itself, which only ever receives a single
already-selected `spouse` prop):
```javascript
function selectDisplayedSpouse(member) {
  const spouses = member.spouses || [];
  return spouses.length > 0 ? spouses[spouses.length - 1] : null;
}
```

**Forward-note (D-14, not this phase's scope):** `selectDisplayedSpouse()`
currently has no owner in the roadmap. `PersonCard` structurally enforces
"single spouse" by only ever accepting one already-selected `spouse` prop
(never a `spouses[]` array), which is correct and sufficient for Phase 25.
But *which* spouse gets selected before being passed in is not implemented
anywhere yet — it is explicitly the responsibility of whichever phase (26 or
27) builds the page/nav layer that constructs the `spouse` prop passed into
`PersonCard`. This note exists so that responsibility is not silently dropped
at milestone close; the next phase that wires `PersonCard` into a real page
must implement (or explicitly re-confirm) `selectDisplayedSpouse()`.
