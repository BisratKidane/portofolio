# Phase 17 — UI Design Contract

> Visual and interaction contract for the `/family` deep tree visualization. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Design-system posture:** This app already ships a mature, single-source-of-truth MUI 6 theme (`frontend/src/theme.js`). shadcn does **not** apply and was **not** initialized — a complete token system, type ramp, and component-override layer already exist. This contract binds the *new* `/family` surface to that existing system; it does not introduce a parallel design language. Every token below is pre-populated from `theme.js` + Phase 17 CONTEXT/RESEARCH decisions. No user questions were required.

## Spacing Scale

MUI's base-8 spacing is already in use throughout (`spacing={2}` = 16px, `spacing={1}` = 8px in `MemberCard.jsx`/`AppLayout.jsx`). Declared 8-point scale (multiples of 4):

| Token | Value | MUI expr | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `0.5` | Icon-to-label gap inside a node, chip inner padding |
| sm | 8px | `1` | Node internal vertical rhythm (name → years), control-button gaps |
| md | 16px | `2` | Node content padding, detail-panel section spacing, avatar-to-text gap |
| lg | 24px | `3` | Detail panel outer padding, control-cluster inset from canvas edge |
| xl | 32px | `4` | Page container top padding (mobile), panel group separation |
| 2xl | 48px | `6` | — (available; not required on this canvas surface) |
| 3xl | 64px | `8` | Page container top padding (desktop, matches `AppLayout` `py: 7`≈56–72) |

**Exceptions (canvas layout constants, not spacing tokens):**
- **Node dimensions** (dagre layout inputs, RESEARCH Pattern 2): person node `180×64px`; synthetic union node `24×24px`. These are graph-geometry constants passed to `layoutWithDagre`, not padding/margin — they live in `familyTree.assembly.js` / the dagre config, not in `sx` spacing.
- **Dagre rank/node separation:** `ranksep: 90`, `nodesep: 60`, `edgesep: 10` (RESEARCH Pattern 2). Layout-engine tuning, spike-adjustable per D-12.
- **Touch targets:** interactive controls (find-me, zoom, expand toggles, node click surface) keep a **≥44×44px** hit area, matching the established `minWidth: 44 / minHeight: 44` pattern in `MemberCard.jsx`.

## Typography

The theme's full type ramp (Inter body + Sora display, weights 400/600/700/800) already governs headings app-wide. The **new tree surface introduces exactly two text weights** — Regular 400 and Semibold 600 — for node and panel body text; headings inside the read-only detail panel reuse the theme's existing Sora display scale.

| Role | Size | Weight | Line Height | Applied to |
|------|------|--------|-------------|------------|
| Node name (Label) | 14px (0.875rem) | 600 (semibold) | 1.3 | Member full name inside `MemberNode` |
| Node years / Body | 12px (0.75rem) | 400 (regular) | 1.4 | `1932–2001` birth–death line; muted `colors.slate` |
| Panel heading | 20px (1.25rem) | 700 (Sora, inherited `h6`/`h5`) | 1.2 | Member name at top of `MemberDetailPanel` |
| Panel body / labels | 14px (0.875rem) | 400 / 600 | 1.5 | Field labels (600) + values (400) in the detail panel |

- **Two declared new weights:** 400 (regular), 600 (semibold). Panel/page headings intentionally inherit the theme's Sora 700/800 display weights — this is the existing app-wide system, not a new decision for this phase.
- Body line-height 1.5; heading line-height 1.2 (matches theme conventions).

## Color

Sourced verbatim from `theme.js` `colors`. The `/family` canvas is dominated by the app's page surface; nodes/panels are the secondary layer; accent is reserved for the personal-landing and active-control cues.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f5f6fb` (`colors.bg`) + theme radial-gradient wash | The pannable canvas/viewport background (the largest visual field) |
| Secondary (30%) | `#ffffff` (`colors.paper`) | Member node cards, detail panel/popover, control cluster, minimap frame |
| Accent (10%) | `#6366f1` (`colors.primary`) / `colors.gradient` | Reserved list below — never applied to every interactive element |
| Destructive | `#ef4444` (`colors.error`) | **Not used this phase** — `/family` is read-only (D-08); no destructive actions exist here |

**Accent (`#6366f1` / gradient) reserved for — explicit list:**
1. The **viewer's own node** highlight ring (`2px solid #6366f1`, `outlineOffset: 2px`) — the "jump-to-me" landing cue (D-02/D-09a).
2. The **find-me / recenter** primary control (filled/gradient, matching `containedPrimary`).
3. **Focus-visible** outlines on keyboard-focused nodes and controls (`2px solid colors.primary`, matches `MemberCard.jsx` focus pattern).
4. **Active expand/collapse toggle** and selected-node edge emphasis.

Accent is **not** used for: ordinary node borders (use `colors.line` `#e6e8f0`), zoom/minimap chrome (neutral), or descent/marriage edges (neutral greys — exact styling spike-driven per D-12).

**Semantic gender-cue exception (D-09b — must NOT be color-only):** the gender indicator pairs a distinct **icon** with a tint, so color is never the sole channel. Tints are a documented semantic exception to the 60/30/10 accent budget:
| Gender | Icon (`@mui/icons-material`) | Tint | Non-color channel |
|--------|------------------------------|------|-------------------|
| Male | `MaleRounded` | cool blue (e.g. `#3b82f6`) | icon shape + `aria-label="Male"` |
| Female | `FemaleRounded` | rose (e.g. `#ec4899`) | icon shape + `aria-label="Female"` |
| Other | `TransgenderRounded` | `colors.slate` neutral | icon shape + `aria-label="Other"` |

The icon carries the meaning; the tint is reinforcement only. Exact tints are executor discretion within the theme palette, provided each remains AA-legible against the white (`#ffffff`) node surface and is always accompanied by its icon + accessible label.

## Copywriting Contract

`/family` is a read-only viewing surface (D-08). There is **no create/submit CTA** and **no destructive action**; the "primary action" is the personal-navigation control.

| Element | Copy |
|---------|------|
| Primary control (jump-to-me) | **"Find me"** — recenters and highlights the viewer's own node (D-02/D-05) |
| Secondary controls | "Search by name" (input placeholder), "Fit to view", "Reset", "Zoom in" / "Zoom out" (aria-labels) |
| Loading state | **"Building your family tree…"** (with skeleton/progress; render matches app's existing async patterns) |
| Empty state heading | **"Your family tree is empty"** |
| Empty state body | **"Family members added on the Manage page will appear here as a tree."** — links to `/manage` (linked members with edit scope) |
| Error state | **"We couldn't load your family tree."** + secondary line **"Check your connection and try again."** + a **"Retry"** action (re-issues the single `familyMembers` query) |
| Node hidden-branch affordance | **Count badge** on collapsible nodes (Claude's-discretion resolved to count over plain toggle): e.g. `+3`, with `aria-label="Show 3 hidden descendants of {name}"` (expand) / `"Hide descendants of {name}"` (collapse) |
| Detail panel — missing dates | **"Dates unknown"** when both birth/death are absent; a lone side renders as `1932–` or `–2001` |
| Detail panel — empty relationship | **"No recorded {parents/spouse/children/siblings}"** for an empty relationship group |
| Destructive confirmation | **None** — no destructive actions on this read-only surface |

## Interaction & State Contract (phase-specific)

Load-bearing behavioral contracts the executor must honor. Derived from CONTEXT D-01…D-15 + RESEARCH patterns.

### Node anatomy (`MemberNode` — D-07)
Left-to-right / top-to-bottom within a `180×64px` card: `MemberAvatarImage` (reused from Phase 16, generic-person fallback) · full name (14px/600) · birth–death years line (12px/400, muted) · gender indicator (icon + tint, top-right or inline). White surface, `1px solid colors.line`, theme `borderRadius`.

### Node states
| State | Visual |
|-------|--------|
| Default | White card, `colors.line` border |
| Viewer's own node (D-09a) | `2px solid colors.primary` ring + a small **"You"** chip/label (not color-only) |
| Focus-visible (keyboard) | `2px solid colors.primary` outline, `outlineOffset: 2px` (matches `MemberCard.jsx`) |
| Selected (detail open) | Accent edge emphasis on the node whose panel is open |
| Collapsible (has hidden children) | Count-badge affordance (`+N`) per copywriting contract |
| Not draggable | `nodesDraggable={false}` — read-only; no drag interactions (RESEARCH Pitfall 3) |

### Detail panel (`MemberDetailPanel` — D-08)
Node click opens a **read-only popover/side-panel** rendered from already-in-memory data (no new fetch — RESEARCH anti-pattern). Contents: photo, full name (20px/700 Sora), gender, birth/death dates, phone, address, and relationship groups (Parents · Spouse · Children · Siblings, siblings derived client-side). **No edit/inline-mutation affordance** (CUR-01 deferred). Dismiss via close button + escape/outside-click.

### Navigation controls (D-05 — ship all four)
1. **Find-me / recenter** button (accent, primary control) — `fitView({ nodes: [{ id: viewerId }] })`; if the viewer node is inside a collapsed branch, expand its ancestor chain first, then center on next tick (RESEARCH Pattern 4 gotcha).
2. **Name search + pan-to** — text input; matching walks-up + expands the target's ancestors, then frames it.
3. **Zoom controls + fit-to-view/reset** — xyflow `<Controls>` (zoom in/out, fit).
4. **Minimap** — xyflow `<MiniMap>` (native; **conditional on the xyflow path** per D-06 — if the spike forces `family-chart`, minimap is dropped, not reimplemented).

Controls sit in an xyflow `<Panel>` cluster on the white secondary surface, inset `lg` (24px) from the canvas edge.

### Initial render (D-03/D-04 — SC-3 performance)
Collapsed-by-default via `node.hidden` (RESEARCH Pattern 3). Initial expand set = the ancestral spine (apex → viewer) **plus** the viewer's own direct line (direct ancestors, direct descendants, spouse, siblings). All collateral branches (cousins, aunts'/uncles' descendants) and other disconnected apex roots start collapsed behind expanders. On load, auto-pan to + highlight the viewer's node.

### Layout & spouse pairing (D-10/D-11/D-12)
Vertical top-down (`rankdir: TB`), apex ancestors at top. Spouses paired via **synthetic union node** (marriage edge `minlen:0` keeps couple same-rank; descent edge `minlen:1` to shared children). **Exact spouse-pairing visual and edge styling (marriage vs descent) are spike-driven (D-12)** — locked after the SC-1 spike proves what renders cleanly at ~10–23 generation depth. If the spike genuinely fails, fall back to `family-chart` (integration shape changes, per RESEARCH anti-pattern 4).

### Accessibility
- Gender cue never color-only (icon + `aria-label` — D-09b).
- Viewer highlight paired with a "You" text label, not color alone.
- Focus-visible outlines on all interactive nodes/controls.
- Node click surface + controls ≥44px touch target.
- Search/find-me results announced (target framed, not silently panned).
