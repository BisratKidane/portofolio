<objective>
Close the core threat this phase exists to fix: a JWT issued before a password reset must stop being honored. Add a seconds-floor, null-safe comparison of `payload.iat` against `user.passwordChangedAt` inside `getUserFromRequest`, proven first by a mandatory direct unit test (the same-second boundary pin required by ROADMAP SC-3) and second by a supplementary HTTP-level test that exercises the real resolver -> hook -> DB -> context wiring end-to-end.

Purpose: SESS-03 is the per-request enforcement half of this phase. Getting the precision direction wrong (ms vs. seconds, `<` vs `<=`) either fails to revoke stale tokens or self-invalidates a freshly issued post-reset token in the same second — the exact bug D-01/D-02 pin down. The existing `graphql()` test helper bypasses this function entirely (RESEARCH Pitfall 2), so this plan's mandatory test must call `getUserFromRequest` directly.
Output: revocation check in `getUserFromRequest`; a 3-test mandatory unit-test block in `auth.test.js`; a supplementary HTTP-level regression test proving the full stack respects the same-second boundary against a real MySQL `DATETIME(3)` column.
</objective>

export function signToken(user) {
  return jwt.sign({ sub: user.id, role: user.role }, env.jwtSecret, { expiresIn: env.jwtExpiresIn });
}

export async function getUserFromRequest(req, models) {
  const header = req.headers.authorization || '';
  const token = header.startsWith('Bearer ') ? header.slice(7) : null;
  if (!token) return null;
  try {
    const payload = jwt.verify(token, env.jwtSecret);
    return models.User.findByPk(payload.sub);
  } catch {
    return null;
  }
}
