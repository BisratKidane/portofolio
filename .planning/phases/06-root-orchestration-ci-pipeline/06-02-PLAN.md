<objective>
Prove, against real GitHub infrastructure (not just local reasoning), that the CI pipeline built in 06-01 actually does what CI-01/CI-02/CI-03 require: a push triggers a real Actions run that provisions its own MySQL and goes green when tests pass, and goes red when a test fails -- with the visible red status confirming CI-03's "a red build is visible on the PR" requirement is genuinely met, not merely wired.

Purpose: 06-01 is entirely file-authoring (a script, a YAML file, a doc section). None of it has ever actually executed on GitHub's infrastructure. GitHub Actions services containers, action version pins, and health-check syntax can all look correct and still fail for reasons only visible in a live run (auth, network, image pull, timing). This plan is the live-fire test that closes that gap before the phase is considered done.
Output: a confirmed green Actions run for the pushed .github/workflows/ci.yml, and a confirmed-then-reverted red Actions run proving CI-03, with backend/src/smoke.test.js left in its original passing state.
</objective>
