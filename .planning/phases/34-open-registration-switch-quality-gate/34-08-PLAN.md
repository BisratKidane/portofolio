<protocol>
For every mutation, in order, and one at a time:
1. Apply the mutation to the named source file.
2. Run the named command and WAIT for it to finish. Never background it, never start a second backend test process, never run two mutations concurrently. A SIGKILLed run leaves a `TRUNCATE` holding a metadata lock that blocks the next `globalSetup` `sync({ force: true })` indefinitely — the symptom is a hang right after the vitest banner at near-zero CPU, and `KILL` does not clear it (recovery needs a full MariaDB stop / `pkill` / start ladder).
3. Record, verbatim: the failing test name(s) and the first assertion failure message (the `AssertionError` line plus its `Expected` / `Received`). A row that says only "confirmed red" does not satisfy D-13.
4. If the command is GREEN, stop. That is a real finding, not a nuisance: the test does not actually protect the guard. Record it as a FAILED mutation, restore the mutation, and report it in the summary as a blocker rather than continuing.
5. Restore the source file to its committed state (`git checkout -- <file>` is the safest restore) and re-run the same command to confirm it is green again.
6. `git status --porcelain` must be clean of source changes before moving to the next mutation.
</protocol>
