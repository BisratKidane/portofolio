<objective>
Build the GraphQL surface of the switch: the public read, the admin read with attribution, and the admin-only flip mutation that writes both the setting row and its audit trail atomically.

Purpose: ADMIN-01 requires the door be closable from inside the app without a redeploy; ADMIN-03 requires the current state be visible where it is changed. D-03 makes the `AuditLog` row the only durable history of a self-overwriting value, which is why this is the codebase's first in-transaction, awaited `writeAuditLog` caller — a lost audit write here is unrecoverable information about a spam incident, unlike the five existing fire-and-forget call sites whose primary effect is durably visible elsewhere.

Output: `setting.schema.js`, `setting.resolver.js`, both barrels wired, and the settings-layer half of `publicRegistrationSwitch.test.js`. Plan 34-05 appends the D-02/D-07/D-08 register-agreement half to the same test file.

  type PublicRegistrationSetting {
    enabled: Boolean!
    updatedAt: String
    updatedByName: String
  }
  extend type Query {
    publicRegistrationEnabled: Boolean!          # PUBLIC / unauthenticated (D-07 — name locked by D-07)
    publicRegistrationSetting: PublicRegistrationSetting!   # requireAdmin (D-06 attribution)

  extend type Mutation {
    setPublicRegistrationEnabled(enabled: Boolean!): PublicRegistrationSetting!   # requireAdmin
  }

Payload semantics (the three D-06 attribution variants UI-SPEC renders):
  updatedAt === null                          -> "Not changed since setup."      (row absent, or row.updatedById IS NULL — the migration-seeded state)
  updatedAt !== null && updatedByName === null -> "Opened/Closed by an administrator on {date}."  (flipped by a user id that no longer resolves)
  updatedAt !== null && updatedByName !== null -> "Opened/Closed by {name} on {date}."
  // updatedAt is the row's Date; GraphQL String coercion calls valueOf() and yields an epoch-ms
  // string (e.g. "1757404800000") — the exact shape AdminMemberTable.jsx:21-26's formatWhen parses.

<open_questions_resolved>
- **CONTEXT F-01 — audit row vs denormalized columns: BOTH, written atomically.** The flip writes `app_settings.updatedById`/`updatedAt` (cheap page-load attribution for D-06) **and** an `AuditLog` row (D-03's deliberate history) inside one `sequelize.transaction`. D-03's ban is on dropping the audit row *in favour of* the columns; nothing is dropped. Reading attribution from `audit_logs` instead would need `WHERE action = ... ORDER BY createdAt DESC LIMIT 1` plus a join to `users`, where the row already read has the answer.
- **Two root fields, not one.** `publicRegistrationEnabled` is called by an anonymous visitor; attaching `updatedByName`/`updatedAt` to it would publish who administers the system and when they acted, on a public page. The single-field alternative (null attribution for non-admins, the `familyMember.schema.js:36-38` pattern) was rejected because D-07 names `publicRegistrationEnabled: Boolean!` literally.
</open_questions_resolved>
