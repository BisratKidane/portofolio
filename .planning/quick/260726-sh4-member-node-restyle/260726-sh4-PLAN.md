# Quick Task 260726-sh4: Restyle MemberNode card

## Goal

Redesign the `/family` tree node card (`MemberNode.jsx`) into a two-column card:

- **Left column = 1/3 of the card width**: the person's photo/avatar.
- **Right column = 2/3**: stacked rows, top to bottom:
  1. **Reserved free row** (empty for now — a future "edit" control will live
     here; the user explicitly deferred the edit icon).
  2. **Full name** row (with the existing "You" chip when `isViewer`).
  3. **Birthday** row — the person's `birthdate`, formatted.
  4. **Mother name** row — the linked mother's full name, else the stored text
     field: `member.mother?.fullname || member.mothersname`.
  5. **Address** row — ONLY when the person is alive (`deathdate == null`) and an
     address exists.

Rows 3–5 are hidden individually when they have no data. Row 1 (reserved) and
row 2 (full name) always render.

## Must preserve (do NOT regress)

- Gender depicted by card colour (border + soft tint), `data-gender`,
  `aria-label`, `title` (no gender icon) — current behavior.
- Viewer ring (`outline`, `data-viewer-ring`) + "You" chip when `isViewer`.
- Descendant/ancestor expand badges (`hiddenCount` / `ancestorHiddenCount`
  IconButtons and their aria-labels + onToggle handlers).
- All FOUR React Flow `<Handle>`s (child-target/top, parent-source/bottom,
  spouse-source/right, spouse-target/left) with their exact ids — edges break
  without them.
- `data-testid={`member-node-${member.id}`}`.

## Data plumbing

The node needs mother name + address, and the mother's linked full name. Update
the tree query in `frontend/src/pages/FamilyTreePage.jsx` (`FAMILY_TREE_QUERY`):

- Add `mothersname` and `address` to the `familyMembers` selection.
- Change `mother { id }` → `mother { id fullname }`.
- Leave `father { id } spouses { id } children { id }` as-is.
- Do NOT add any admin-only/account-link field (the query's existing D-14
  security note still applies — `mothersname`/`address`/`mother.fullname` are
  ordinary FamilyMember fields, already exposed on /manage).

No backend change (schema already exposes `mothersname`, `address`, and
`mother: FamilyMember`).
