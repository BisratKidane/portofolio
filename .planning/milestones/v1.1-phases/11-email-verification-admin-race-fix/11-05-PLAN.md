## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Concurrent `verifyEmail` calls racing for the single ADMIN slot | Two different users, two different valid tokens, potentially the same wall-clock instant |
| `resendVerificationEmail`'s response vs. account existence/verification state | Must not leak which of the three states (unverified / verified / nonexistent) produced the response |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05a | Elevation of Privilege | `verifyEmail`'s ADMIN assignment | mitigate | Atomic conditional `UPDATE ... WHERE role != 'ADMIN' AND NOT EXISTS (...)`, run only after the token-consumption update has already succeeded for this specific user — proven race-safe by a genuine `Promise.all` concurrency test (Task 1, Test 5) showing exactly one winner, and a filled-slot test (Test 6) proving the slot is never reopened. |
| T-11-05b | Tampering (token) | `verifyEmail`'s token consumption | mitigate | Single-use enforced by the same atomic-conditional-UPDATE technique as `resetPassword`'s WR-02 fix — a second use of the same token after the first success cannot succeed (Task 1, Test 4). |
| T-11-05c | Information Disclosure | `resendVerificationEmail` | mitigate | Identical generic message + timing floor for unverified / already-verified / nonexistent accounts (Task 2, Tests 2-4) — closes the enumeration oracle the reset flow already closed, applied here to the verification flow. |
| T-11-05d | Denial of Service | `resendVerificationEmail` spam | mitigate | Rate-limited to 5/hour via the `RATE_LIMITS` entry added in Plan 11-02; the rate-limit plugin enforces it automatically now that the resolver exists, and Task 2's Test 5 is a dedicated enforcement proof (a 6th call from the same IP is rejected with the generic too-many-requests error), matching the RATE-01..05 proof pattern already established for `login`/`register`/`requestPasswordReset`. |
</threat_model>
