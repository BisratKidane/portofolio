## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-13-01 | Elevation of Privilege | `requireFamilyAccess` in `backend/src/utils/auth.js` | accept | The carve-out checks `user.role === 'ADMIN'` directly (not a separate "is-bootstrap-admin" flag), so EVERY current and future ADMIN permanently bypasses the linked-member requirement. This is the explicit, documented D-06 design ("any ADMIN bypasses... no special-casing which admin is the bootstrap one") and is bounded because ADMIN is already an admin-granted, privileged role — not something a regular user can self-assign. |
| T-13-02 | Tampering | `requireFamilyAccess` input | mitigate | `familyMemberId` is read from the server-resolved `User` model instance attached to context via `getUserFromRequest`/DB lookup, never from client-supplied GraphQL arguments — client-side tampering with a JWT payload or request body has no effect on the guard's decision. |
| T-13-03 | Denial of Service / Data corruption | `012-add-users-family-member-id.sql` | mitigate | The column is nullable with NO backfill and NO `UPDATE` statement touching existing rows (mirrors `009`'s zero-backfill precedent). `database.test.js`'s automated tests prove the equivalent DDL applies cleanly via `sync()` on a disposable test database before a human ever runs it against a real one. |
