<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Application code → self-referencing FK constraints | Any create/update touching `motherId`/`fatherId`/`memberAId`/`memberBId` crosses from in-process Sequelize calls into real MySQL foreign-key enforcement — this is the first association-bearing model in the codebase. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-------------------|
| T-12-04 | Tampering | `motherId`/`fatherId` FK constraint config | mitigate | `onDelete`/`onUpdate` declared exactly once, on the `belongsTo` side only, per RESEARCH.md's cited Sequelize conflicting-option bug (sequelize/sequelize#16526); proven by the cascade-SET-NULL test in Task 1. |
| T-12-05 | Tampering | `Spouse` canonical pair uniqueness | mitigate | DB-level `UNIQUE(memberAId, memberBId)` index + `beforeValidate` ordering hook eliminates the swapped-order duplicate-insert race (TOCTOU); proven by the unique-constraint-rejection test in Task 2. |
| T-12-06 | Tampering / Integrity | `Spouse` self-marriage | mitigate | Model-level `notSelfMarriage` validator rejects `memberAId === memberBId`; proven by the self-marriage-rejection test in Task 2. |
| T-12-07 | Tampering | Orphaned FK reference (`motherId` pointing at a nonexistent row) | mitigate | `allowNull: true` on both `motherId`/`fatherId` foreign keys + real MySQL FK constraint rejects any create/update referencing a nonexistent parent id; proven by the FK-rejection test in Task 1. |
</threat_model>
