<objective>
Ship `addChild` and `addSibling` — the mutation pair that carries this phase's primary
security-boundary test (SC-4): `addChild`'s optional `otherParentId` is the one argument in this
entire phase where a member-user references an EXISTING node id to complete a relationship
(D-02's "add my child, with my existing spouse as the other parent" example), making it the exact
surface the adversarial escalation test must attack.

Purpose: prove the D-02 invariant directly — "a member may only wire together nodes they already
control; their scope grows only by creating new nodes, never by referencing existing ones" — with
a test that attempts to reference a stranger's linked member and a grandparent as `otherParentId`,
both rejected. Also ship `addSibling`, REL-04's mutation-side counterpart to the read-side
derivation shipped in 14-03, including the mandatory D-04 no-parent-recorded rejection.
Output: `addChild`/`addSibling` mutations, SDL, and tests, including the SC-4 adversarial cases.
</objective>
